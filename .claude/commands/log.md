이번 세션의 작업을 위키에 기록해줘. 위키 저장소: ../giltara.wiki

## 언제 실행하나
- PR 초안을 쓰기 전 (PR 본문의 "AI 활용 > 상세 기록"에 위키 링크를 넣기 위해)
- 이슈를 끝내지 못한 채 세션을 닫을 때 (세션 대화가 사라지기 전에)
- 까다로운 오류를 해결한 직후

## 순서
1. 위키 저장소에서 git pull
2. 이번 세션 대화와 커밋 내역을 바탕으로 아래 형식의 초안 작성
3. 초안을 보여주고 "AI 결과에서 직접 수정한 부분"을 나에게 물어본 뒤 반영
4. 내가 확인하면 "docs: #이슈번호 작업 기록"으로 커밋 후 push
5. 추가한 항목의 위키 링크를 알려줌 (PR 본문에 쓸 수 있게)

## 프롬프트-로그-구현.md
제목·설명 바로 아래 `---` 다음에 추가 (기존 항목은 수정하지 않음). 항목 끝에는 `---` 구분선을 둔다.

```
## [YYYY-MM-DD] 작업 제목 (#이슈번호, PR #번호)

- **목적**:
- **핵심 프롬프트**: (실제 입력한 문장. 여러 번 고쳤다면 순서대로)
- **결과**:
- **직접 수정한 부분**:
- **프롬프트를 바꾼 이유 / 배운 점**:
```

- 프롬프트-로그-기획.md에 같은 작업의 기획 결정이 있으면 `[[프롬프트 로그 기획]]`으로 링크한다.
- 기획 때 정한 내용이 구현 중 바뀌었다면, 기획 로그의 해당 항목 끝에 `- → 구현 중 변경: ... ([[프롬프트 로그 구현]] 날짜 참고)` 한 줄만 추가한다. 이 경우에만 기존 항목을 수정할 수 있다.

## 트러블슈팅.md (오류를 해결한 경우에만)
같은 위치·형식으로 추가한다.

```
## [YYYY-MM-DD] 문제 제목 (#이슈번호)

- **문제**: (오류 메시지 핵심)
- **원인**:
- **해결**:
- **배운 점**:
- **CLAUDE.md 반영**: (규칙을 추가했다면)
```

## 규칙
- API 키, 토큰, .env 값은 절대 기록하지 않음
- 해결한 오류가 없으면 트러블슈팅은 건너뜀
- 하위 목록은 공백 4칸으로 들여씀
